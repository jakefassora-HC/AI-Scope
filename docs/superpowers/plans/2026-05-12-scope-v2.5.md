# scope v2.5 Implementation Plan — Region Map

> Supplements v2 (System Map). Replaces the flat starburst with a compound-region "world map" using Cytoscape parent nodes + fcose layout.

**Goal:** Each project is a labeled bounded region. Landmark files (CLAUDE.md, README, manifest) live visually inside their region. Worktrees are nested children. Running `claude` processes glow on the region they're cwd'd into. Click a region to zoom in.

**Why:** The v2 starburst has no hierarchy — five `CLAUDE.md` nodes with no parent context. Compound nodes fix the structural problem at the root. Tree view was rejected because the File Browser tab already does that; the Map needs to be *visual*, not a list.

## Library swap

- **Remove:** `cytoscape-dagre@2.5.0` (tree layout, doesn't handle compound parents well)
- **Add:** `cytoscape-fcose@2.2.0` (force-directed; compound-aware; current best-in-class for grouped graphs)

## Per-repo landmark files

For each repo we include these files as visible child nodes (if present at the repo root):
- `CLAUDE.md`
- `README.md`
- The first matching manifest: `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `requirements.txt`

That's at most 3 file nodes per region — keeps the diagram readable. Deeper file exploration is what the File Browser tab is for.

## Node hierarchy

```
home                              ─ top-level "globe" node (small, centered)
├─ region:.claude                 ─ compound parent
│   ├─ config:CLAUDE.md
│   ├─ config:settings.json
│   ├─ config:settings.local.json
│   └─ region:.claude/rules       ─ nested compound (if rules/ exists)
│       └─ config:workflow.md, ...
└─ region:projects                ─ compound parent
    ├─ region:scope               ─ each repo is a compound parent
    │   ├─ config:CLAUDE.md       ─ landmark file
    │   ├─ config:README.md
    │   └─ config:pyproject.toml
    ├─ region:foo
    │   ├─ config:CLAUDE.md
    │   └─ region:worktrees/foo-fix-x  ─ worktree nested inside parent repo
    └─ region:human-road-warrior
        └─ ... + has_process glow on the region
```

Edges become near-obsolete in compound layout (parent containment expresses relationships). We still keep:
- Dotted `process` edge from process node → its region (visually attaching).
- No other edges. The container relationship IS the visual.

### Task 1.5: Update /api/graph route

**Files:** `app.py`

- [ ] **Step 1:** Update the `api_graph` route to pass a real `list_landmarks` that uses `os.scandir` over each repo. Keep it inline (no new module). 10-line helper:
```python
def _list_landmarks(repo_path: str) -> list[dict]:
    from os import scandir
    from os.path import join
    from datetime import datetime, timezone
    from scope.token_estimator import estimate_tokens_from_bytes
    names = {"CLAUDE.md", "README.md", "package.json", "pyproject.toml",
            "Cargo.toml", "go.mod", "requirements.txt"}
    out = []
    try:
        for entry in scandir(repo_path):
            if entry.name not in names or not entry.is_file(follow_symlinks=False):
                continue
            stat = entry.stat(follow_symlinks=False)
            mtime = datetime.fromtimestamp(stat.st_mtime, tz=timezone.utc)
            out.append({
                "path": entry.path, "name": entry.name,
                "size_bytes": stat.st_size,
                "tokens_est": estimate_tokens_from_bytes(stat.st_size),
                "modified_iso": mtime.isoformat(timespec="seconds"),
                "age_days": (datetime.now(tz=timezone.utc) - mtime).days,
                "auto_loaded": entry.name == "CLAUDE.md",
            })
    except (OSError, PermissionError):
        pass
    return out
```
